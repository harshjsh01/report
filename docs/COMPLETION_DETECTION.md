# 🤖 Automatic Completion & Milestone Detection Engine

GitPulse features an automated analysis engine that inspects repository attributes, deployment signals, markdown checklists, tags, and issue states to automatically identify whether a project is **Completed**, **Version 1.0 Complete**, **Needs Polish**, or **In Progress**.

---

## 🎯 Detection Hierarchy & Rules

When repositories are audited, GitPulse runs each project through the following rule pipeline:

```
                  ┌──────────────────────────────┐
                  │      Inspect Repository      │
                  └──────────────┬───────────────┘
                                 │
                   Is repo archived on GitHub?
                     ├─► YES ──► 📦 Status: ARCHIVED
                     │
         Has release tag matching v1.0+ (e.g. v1.0.0)?
                     ├─► YES ──► 🏆 Status: VERSION 1.0 COMPLETE
                     │
           Are 100% of markdown tasks checked [x]?
                     ├─► YES ──► 🏆 Status: VERSION 1.0 COMPLETE
                     │
          Has live URL (Vercel/Netlify) & 0 open issues?
                     ├─► YES ──► 🏆 Status: VERSION 1.0 COMPLETE
                     │
         Has live URL, but has open issues to resolve?
                     ├─► YES ──► 🔍 Status: NEEDS POLISH
                     │
          Has pre-release tag (v0.x, beta, alpha, rc)?
                     ├─► YES ──► 🔍 Status: NEEDS POLISH
                     │
           Are >= 75% of markdown tasks checked [x]?
                     ├─► YES ──► 🔍 Status: NEEDS POLISH
                     │
        No push > 90 days, 0 issues, has code/description?
                     ├─► YES ──► ✅ Status: COMPLETED
                     │
           Active commits in last 45 days or open issues?
                     └─► YES ──► 🚀 Status: IN PROGRESS
```

---

## 🔍 Detailed Criteria

### 1. 🏆 Version 1.0 Complete (`v1_complete`)
A project is automatically classified as **v1.0 Complete** if **any** of the following conditions are met:
1. **Official Release Tag**: A git tag or GitHub release exists matching `v1.x`, `v1.0.0`, `1.0.0`, or higher.
2. **Shipped Production Deployment**: The repository has a working `homepage` URL (e.g., hosted on Vercel, Netlify, GitHub Pages, or a custom domain) AND has **0 open issues**.
3. **100% Documentation Task Completion**: The repository contains markdown checklists (`TODO.md`, `TASKS.md`, `README.md`) where all tasks are checked off (`- [x]`).

### 2. ✅ Completed (`completed`)
A project is classified as **Completed** (historic milestone or finished utility) when:
- It has **0 open issues** and **0 open PRs**.
- Last pushed more than 90 days ago.
- Contains working codebase, description, and/or license.
- Examples: Completed prototypes, course projects, or finished libraries.

### 3. 🔍 Needs Polish (`needs_polish`)
A project is classified as **Needs Polish** when:
- It has a live deployment URL, but still has **open issues** reported.
- It has pre-release version tags such as `v0.8`, `v0.9`, `beta`, `alpha`, or `rc`.
- Between **75% and 99%** of markdown tasks are completed.

### 4. 🚀 In Progress (`in_progress`)
- Active commits within the past 45 days.
- Open backlog issues or open pull requests undergoing review.
- Incomplete markdown tasks (< 75%).

### 5. 📦 Archived (`archived`)
- The repository is marked as archived via GitHub repository settings.
